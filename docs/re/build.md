# Build and identity

`build.py` unpacks every block listed in `tools/blocks.py` from the original ROM and packs it back into a copy;
`tests/test_identity.py` asserts the result equals the original (phase 3, verified 2026-11-01: 60 writes, romdiff clean,
smoke boots). Later phases swap edited entries in between unpack and pack.

## Block kinds
- **PACKED** (story, rescue, boss, system, pause, yesno, titlemenu, tutorial, client_pause, client_link): strings back to
  back from the first pointer, 00 padding to 4, then the u32 pointer table (referenced by code, never moves). Verified
  for all 10: pointers unique + ascending, each string ends exactly at the next pointer (codec per block: story = jp.tbl
  `{end}`, tutorial = `tools/tutorial.py`, msg = FF end with FD/F9 one-arg), padding all 00. Pack: same slot if it fits
  (rest 00-filled), else the whole block moves to free space 0x3529D0+ and the table is repointed. Client blocks (pointer
  base 0x02000000 - 0x32CED4) can't leave the multiboot image: overflow is an error.
- **RECORDS** (fixed size, in place): demon names 167 x 8; link trade 13 x 0x1C (two 14-byte lines, FF padded, stale
  bytes after FF); link transfer 5 x 0x1C; DeviDas trade menu 0x28B0A4 0x1C bytes. Phase 4 defines their fields.
- **LZ** (36 blocks: fonts + every graphics-text block in graphics.md): recompressed in place, slot = original length
  rounded up to 4; a bigger result is an error until that block gets relocation (repoint its xrefs).

## LZ77 compressor (verified)
`tools/lz77.py compress(data, min_disp)` = greedy longest match, nearest on ties, 4096 window, pad 00 to 4. It
reproduces **all 556 blocks** in `work/lzscan.txt` byte for byte: 276 need min_disp 1 (graphics), the rest min_disp 2
(fonts and blocks with no distance-1 match). `lz77.mode()` picks the setting per block; edits reuse it, so a block the
game unpacks with the VRAM routine stays VRAM-safe.

## Script files (phase 4, verified 2026-11-01: tests/test_extract.py)
`python -X utf8 tools/extract.py` dumps the original ROM to `script/<block>.json` (14 files, 852 units); build.py
inserts every non-empty `en`. Entry: `id`, `ptr` (file offset of the unit), `jp`, `en` ("" = keep original bytes),
`max` (record fields, bytes), `data` (not text: build refuses an `en` there). Re-running extract never drops `en`:
same id keeps `en` and extra keys (a changed `jp` sets `recheck`), vanished ids go to `orphans`.
- **Units** (`tools/text.py`): a packed string is decoded with its codec table (`tbl/jp.tbl` story, `tbl/msg.tbl`
  msg, `tbl/tutorial.tbl` tutorial; all generated by `tools/mk_jp_tbl.py`) and split into a skeleton of commands plus
  units = runs of glyphs, colour codes and layout codes, with the layout codes trimmed off both ends. Layout codes:
  story `{n}` and the page triple `{wait:00}{clr}{box:09}`; msg / tutorial `{n}` `{page}`. The skeleton is rebuilt
  from the ROM on every build, so `en` replaces exactly its `jp` and may add layout codes (more lines / pages).
  Ids `<block>.<string>.<unit>`.
- **Record fields** (`blocks.FIELDS`): names 8 (FF pad), trade / transfer two 14-byte lines (FF pad, bytes after the FF
  are stale and kept for unchanged fields), DeviDas menu 4 x 5 (FF pad) + 2 x 4 (00 = fullwidth-space pad). `en` is
  encoded and padded to the field; longer is a build error. Ids `<block>.<record>[.<field>]`. `names.162` (8 x 1C) is data.
- Codecs: msg `FF` end, `FE` {n}, `FC` {page}, `FD xx` {col:xx}, `F9 xx` {f9:xx}; tutorial adds `F8 xx` {demoXX[:args]}
  and `FA xx` {pause:xx}, no F9. No unknown byte (`[XX]`) in any string.
- **Coverage**: blocks tile their ranges exactly (unpack checks), skeletons hold no glyph, and `tools/strayscan.py`
  (glyph runs <= 64 bytes ended by FF/FE/FC with >= 2 common kana words, >= 70% kana) finds 196 sentences in the ROM:
  all inside units, none outside the blocks (one 8bpp-sprite false hit listed in `strayscan.NOISE`).
